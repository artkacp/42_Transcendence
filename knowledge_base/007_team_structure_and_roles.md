# 007 — Team Structure and Roles

## Team size

- 4 or 5 people required
- With 4 members: some will hold multiple roles (PM + Developer is common)
- With 5 members: roles can be more specialised

All roles must be documented in the README.

---

## Required roles

### Product Owner (PO)
- Defines the product vision
- Prioritises features and maintains the backlog
- Validates completed work
- Makes decisions on features and scope

### Project Manager (PM) / Scrum Master
- Facilitates team coordination and removes blockers
- Organises meetings and planning sessions
- Tracks progress and deadlines
- Manages risks and communication

### Technical Lead / Architect
- Defines the technical architecture
- Makes technology stack decisions
- Ensures code quality and best practices
- Reviews critical code changes

### Developer
- All team members are developers in addition to any other role
- Write code for assigned features
- Participate in code reviews
- Test and document their implementations

---

## Recommended practices

- **Regular meetings**: weekly or bi-weekly syncs on progress and blockers
- **Task tracking**: GitHub Issues or similar — track who does what
- **Work breakdown**: divide the project into smaller, manageable tasks
- **Code reviews**: at least one other team member reviews important changes before merge
- **Documentation**: keep notes of important decisions
- **Communication channel**: a dedicated channel for quick team communication

---

## Key risk: unequal contribution

All team members must actively participate in both the mandatory part and the chosen modules. The git commit history is visible — unequal contributions are obvious.

Individual contribution breakdown is required in the README. Each team member is expected to be able to explain the parts they worked on.

---

## Potential evaluation questions

All team members should be able to answer these, not just the PM or PO.

- How were roles distributed across the team?
- How was work organised and divided?
- How did the team communicate and coordinate?
- What did each team member contribute specifically?
- How were blockers or disagreements resolved?
