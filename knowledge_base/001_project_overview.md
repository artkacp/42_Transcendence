# 001 — Project Overview

ft_transcendence is the final project of the 42 Common Core. It is a team-built, full-stack web application where the team defines what to build — the project direction, features, and application type are all chosen by the team.

Unlike previous 42 projects with a fixed specification, this project provides:
- A mandatory technical baseline (what the application must have)
- A module catalogue (optional additions chosen by the team)
- A minimum score threshold to pass

---

## Team

- 4 to 5 people required
- Each team member must actively contribute to both the mandatory part and chosen modules
- Roles must be assigned and documented (see note 007)
- All team members must be able to explain any part of the project at evaluation

---

## Scoring

| Type | Points |
|------|--------|
| Major module | 2 |
| Minor module | 1 |
| Minimum to pass | 14 |
| Maximum bonus | +5 (beyond 14) |

Modules beyond the 14-point minimum may be validated as bonus points, up to 5 extra.

---

## Project structure

### Mandatory part

The fixed core every team must implement regardless of what they build. Covers: application type (web), deployment, security baseline, user authentication, and general quality requirements. See notes 002 and 003.

### Modules

Optional additions chosen from a catalogue of categories. The team must reach 14 points minimum to pass. See note 004.

---

## What this project tests differently

- The problem statement is open — the team defines the application
- Module planning and team coordination are evaluated alongside code quality
- Every team member is expected to understand and explain the full project
- Poor early choices (wrong tech, wrong modules) are expensive to undo in a long team project
