# 006 — README Requirements

The README is a required project artifact. It must be written in English and kept updated throughout development — rewriting it from memory at the end produces poor results.

---

## Required first line

The very first line must be italicised and follow this exact format:

> *This project has been created as part of the 42 curriculum by \<login1\>[, \<login2\>[, \<login3\>[...]]].]*

---

## Required sections

### Description
- Project name and goal
- Brief overview of what the application does
- Key features

### Instructions
- All prerequisites (software, tools, versions, configuration)
- `.env` setup instructions (reference `.env.example`)
- Step-by-step instructions to run the project

### Resources
- References related to the project topic (documentation, articles, tutorials)
- Description of how AI was used: for which tasks and which parts of the project

### Team information
For each team member:
- Assigned role(s): PO, PM, Tech Lead, Developer, etc.
- Brief description of responsibilities

### Project management
- How the team organised the work (task distribution, meetings)
- Tools used for project management
- Communication channels used

### Technical stack
- Frontend technologies and frameworks
- Backend technologies and frameworks
- Database system and justification for the choice
- Any other significant technologies or libraries
- Justification for major technical choices

### Database schema
- Visual representation or description of the database structure
- Tables and their relationships
- Key fields and data types

### Features list
- Complete list of implemented features
- Which team member(s) worked on each feature
- Brief description of each feature's functionality

### Modules
- All chosen modules (Major and Minor) with point values
- Point calculation total
- Justification for each module choice (especially custom modules)
- How each module was implemented
- Which team member(s) worked on each module

### Individual contributions
- Detailed breakdown of what each team member contributed
- Specific features, modules, or components implemented by each person
- Challenges faced and how they were overcome

---

## Optional but useful

- Usage documentation
- Known limitations
- License

---

## Notes

- The contribution breakdown is used to verify that all team members actively participated
- The AI usage disclosure in the Resources section is mandatory — the subject explicitly acknowledges AI-assisted work is expected
- Keep the README updated as development progresses; evaluators cross-reference README claims with the actual application and git history
